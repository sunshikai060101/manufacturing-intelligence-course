# 方案设计

---

## 一、功能需求分析

### 1.1 系统总体功能

本系统面向智能仓储物料分拣场景，实现从物料上料、图像采集、智能识别、多传感器校验、机器人分拣到数据统计的全流程自动化。系统总体功能架构如下：

```
┌─────────────────────────────────────────────────────┐
│                   上位机监控系统                       │
│  (实时监控 / 数据统计 / 参数配置 / 历史查询)          │
└──────────────┬──────────────────┬───────────────────┘
               │ MQTT/HTTP        │ TCP/IP
┌──────────────▼───────┐ ┌────────▼──────────┐
│   视觉识别模块        │ │  机器人控制模块    │
│  (相机采集/YOLO检测)  │ │ (机械臂运动/抓取)  │
└──────────┬────────────┘ └────────┬──────────┘
           │                        │
┌──────────▼────────────────────────▼──────────┐
│            多传感器融合与主控模块               │
│  (重量传感器 / 红外传感器 / 主控逻辑 / 通信)    │
└───────────────────────────────────────────────┘
```

### 1.2 功能模块详细需求

#### 模块一：图像采集与预处理
- 工业相机实时采集传送带上物料图像，帧率不低于 30 FPS；
- 支持图像灰度化、高斯滤波、直方图均衡化等预处理操作；
- 支持相机标定，完成像素坐标到世界坐标的转换。

#### 模块二：物料智能识别与定位
- 基于 YOLOv8 目标检测算法，支持至少 5 类物料的识别与分类；
- 输出物料的类别、置信度、边界框坐标及中心点坐标；
- 单帧推理时间不超过 100 ms，满足实时性要求；
- 识别准确率不低于 90%。

#### 模块三：多传感器融合校验
- 重量传感器采集物料重量信息，与视觉识别结果进行交叉验证；
- 红外传感器检测物料到位状态，触发相机拍摄与分拣动作；
- 采用加权融合策略，综合视觉与传感器数据输出最终判定结果；
- 当视觉与传感器结果不一致时，系统报警并将物料送入复检区。

#### 模块四：机器人自动分拣
- 六轴机械臂根据识别结果规划运动轨迹，完成物料抓取与分类放置；
- 支持抓取点位姿计算、避障路径规划、运动速度可调；
- 分拣节拍不低于 3 秒/件；
- 支持急停、复位、手动/自动模式切换。

#### 模块五：上位机监控与数据管理
- 可视化界面实时显示相机画面、检测结果、分拣状态；
- 统计当日分拣总量、各类物料数量、准确率、误拣率等指标；
- 支持历史记录查询、数据导出（CSV/Excel）；
- 支持系统参数配置（置信度阈值、分拣速度、传感器校准等）。

### 1.3 非功能需求
- **实时性**：从物料到位到完成分拣的总延迟不超过 3 秒；
- **可靠性**：连续运行 2 小时无故障，误拣率低于 3%；
- **可扩展性**：模块化设计，支持新增物料类别与分拣工位；
- **易用性**：上位机界面操作简洁，支持中文显示。

## 二、方案论证

### 2.1 技术路线对比与选型

#### （1）目标检测算法选型

| 算法 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| YOLOv8 | 速度快、精度高、社区活跃、部署方便 | 小目标检测略逊 | 实时分拣（推荐） |
| Faster R-CNN | 精度高、小目标表现好 | 推理速度慢 | 离线高精度检测 |
| SSD | 速度较快 | 精度低于YOLO | 嵌入式实时检测 |

**选型结论**：选用 **YOLOv8**，兼顾实时性与精度，且有完善的开源生态与部署工具，适合课程设计项目。

#### （2）多传感器融合策略选型

| 融合策略 | 原理 | 优点 | 缺点 |
|----------|------|------|------|
| 加权平均融合 | 对多源数据按权重加权求和 | 简单易实现 | 需手动调权 |
| 卡尔曼滤波 | 基于状态空间的递推估计 | 动态性能好 | 适用于线性高斯系统 |
| D-S 证据理论 | 基于证据组合的不确定性推理 | 处理冲突能力强 | 计算复杂度高 |

**选型结论**：选用 **加权平均融合 + 规则校验** 的轻量级方案，视觉结果为主、重量传感器结果为辅，通过预设规则进行一致性判断，实现简单且满足课程设计需求。

#### （3）控制系统架构选型

| 架构 | 优点 | 缺点 |
|------|------|------|
| 单片机（STM32）主控 | 成本低、实时性好 | 算力有限、视觉处理困难 |
| 工控机 + 单片机协同 | 算力充足、分工明确 | 成本较高、通信复杂 |
| 树莓派/边缘计算盒子 | 体积小、算力适中 | 高负载下性能有限 |

**选型结论**：采用 **工控机（上位机）+ STM32（下位机）** 协同架构，上位机负责视觉处理与界面显示，下位机负责传感器采集与机器人通信，分工明确且易于实现。

### 2.2 可行性分析

- **技术可行性**：YOLOv8、OpenCV、PyQt 等均有成熟开源方案，多传感器融合与机器人控制有大量参考案例，技术路线清晰可行。
- **硬件可行性**：工业相机、重量传感器、红外传感器、六轴机械臂（或教学型机械臂）均为实验室常见设备，可通过课程资源或仿真替代。
- **时间可行性**：项目周期约 4-6 周，按模块分解后各阶段任务量适中，可在课程设计周期内完成。
- **经济可行性**：以软件仿真与实验室现有硬件为主，额外成本低。

## 三、方案规划

### 3.1 技术栈

#### 软件技术栈

| 层次 | 技术选型 | 说明 |
|------|----------|------|
| 深度学习框架 | PyTorch | YOLOv8 训练与推理 |
| 图像处理 | OpenCV | 图像采集、预处理、标定 |
| 目标检测 | Ultralytics YOLOv8 | 物料检测与分类 |
| 上位机界面 | PyQt5 / PySide6 | 可视化监控界面 |
| 后端语言 | Python 3.10+ | 主控制逻辑、算法实现 |
| 下位机语言 | C / C++ | STM32 传感器采集与通信 |
| 通信协议 | MQTT / TCP Socket / Serial | 上下位机通信 |
| 数据存储 | SQLite / CSV | 分拣记录存储与导出 |
| 版本控制 | Git + GitHub | 代码管理与协作 |

#### 硬件技术栈（如无实物可纯仿真）

| 模块 | 推荐型号 | 说明 |
|------|----------|------|
| 工业相机 | 海康威视 MV-CA013-10GC / 罗技 C920（替代） | 图像采集 |
| 主控（上位机） | 工控机 / 普通笔记本 | 视觉处理与界面 |
| 主控（下位机） | STM32F103C8T6 | 传感器采集与控制 |
| 重量传感器 | HX711 + 称重传感器模块 | 重量检测 |
| 红外传感器 | E18-D80NK 红外避障模块 | 物料到位检测 |
| 机械臂 | 遨博/越疆教学型六轴机械臂 / 仿真模型 | 分拣执行 |
| 传送带 | 直流减速电机 + 传送带模组 | 物料输送 |

### 3.2 需配置的外部资源

- **GitHub 仓库**：用于代码托管与版本管理，需创建公开仓库；
- **PyTorch 环境**：需配置 CUDA（如有 GPU）或 CPU 版本的 PyTorch 环境；
- **Ultralytics 库**：`pip install ultralytics`，用于 YOLOv8 训练与推理；
- **MQTT Broker**：可使用公共 Broker（如 `broker.emqx.io`）或本地部署 Mosquitto；
- **LabelImg / Labelme**：图像标注工具，用于制作训练数据集；
- **机器人仿真环境（可选）**：如无实物机械臂，可使用 CoppeliaSim / MATLAB Robotics Toolbox 进行仿真。

### 3.3 数据集来源

| 数据来源 | 说明 | 数量预估 |
|----------|------|----------|
| 公开数据集 | Google Images / Kaggle 搜索相关物料图片 | 约 500-1000 张 |
| 自行采集 | 使用相机拍摄实际物料图像（不同角度、光照） | 约 300-500 张 |
| 数据增强 | 通过旋转、翻转、缩放、色彩抖动等方式扩充 | 扩充至 2000+ 张 |

**数据集类别建议**（至少 5 类，可根据实际物料调整）：
1. 长方体纸盒
2. 圆柱形易拉罐
3. 球形物体（如乒乓球）
4. 不规则形状零件
5. 袋装物品

**标注格式**：YOLO 格式（`.txt` 文件，每行：`class_id x_center y_center width height`）。

### 3.4 前端 UI 方案

采用 **PyQt5** 开发桌面端上位机界面，整体布局如下：

```
┌──────────────────────────────────────────────────────┐
│  菜单栏：文件 / 系统设置 / 帮助                         │
├──────────────┬───────────────────────────────────────┤
│              │  实时视频显示区                          │
│  左侧面板     │  (相机画面 + 检测框标注)                │
│  - 设备状态   │                                       │
│  - 今日统计   ├───────────────────────────────────────┤
│  - 物料类别   │  检测结果列表                           │
│    管理       │  (序号/类别/置信度/时间/分拣结果)       │
│              ├───────────────────────────────────────┤
│              │  底部控制栏：启动 / 暂停 / 急停 / 手动模式│
└──────────────┴───────────────────────────────────────┘
```

**界面功能要点**：
- 实时显示相机画面与 YOLO 检测框（类别 + 置信度）；
- 设备状态指示灯（相机/传感器/机器人连接状态）；
- 今日分拣统计图表（柱状图/饼图，使用 PyQtGraph 或 Matplotlib）；
- 检测结果表格，支持按时间筛选与导出；
- 参数设置面板（置信度阈值、IOU 阈值、分拣速度等）。

### 3.5 后端算法方案

#### （1）视觉识别算法流程

```
相机采集图像 → 图像预处理(缩放/归一化) → YOLOv8推理
     → 输出检测框(类别/置信度/坐标) → 坐标转换(像素→世界)
     → 结果缓存 → 发送至主控模块
```

#### （2）多传感器融合算法流程

```
红外传感器检测物料到位 → 触发相机拍摄 + 重量传感器读数
     → 视觉识别结果(类别/位置) + 重量读数
     → 规则校验：该类别理论重量范围是否包含实测重量
        ├─ 一致 → 确认结果，触发分拣
        └─ 不一致 → 标记为可疑，送入复检区/报警
```

#### （3）机器人控制算法流程

```
接收物料类别与世界坐标 → 逆运动学求解关节角
     → 轨迹规划( MoveJ / MoveL ) → 运动至抓取点
     → 吸盘/夹爪闭合 → 提升 → 运动至对应料盒上方
     → 释放物料 → 返回等待位
```

#### （4）主控调度逻辑

采用**状态机**模式管理系统运行：

```
[待机状态] → 收到启动指令 → [运行状态]
[运行状态] → 物料到位 → [识别状态] → [校验状态]
[校验状态] → 结果一致 → [分拣状态] → 返回[运行状态]
[校验状态] → 结果不一致 → [报警状态] → 人工处理后返回
[任意状态] → 急停指令 → [急停状态]
```
