## 摘要

本项目设计并实现了一套面向智能仓储场景的物料自动识别与分拣管理系统。系统综合运用机器视觉、深度学习、多传感器数据融合及工业数据分析等技术，实现仓储物料的智能识别、多维度校验、异常检测与库存管理。系统采用B/S架构，前端基于HTML/CSS/JavaScript构建可视化监控界面，后端基于FastAPI框架提供RESTful API服务，数据库采用SQLite进行数据持久化，算法层包含目标检测、多传感器融合、异常检测三个核心算法模块。系统使用SORDI公开工业数据集，选取6类仓储相关物料共2333张图像进行数据处理与模型支撑。经测试，系统43个自动化测试用例全部通过，各功能模块运行正常，达到了课程设计的预期目标。

**关键词：** 机器视觉；目标检测；多传感器融合；异常检测；智能仓储；B/S架构

## 1. 背景调研

### 1.1 研究意义

随着电子商务和智能制造的快速发展，仓储物流作为供应链的核心环节，面临着效率提升和成本控制的双重压力。传统仓储物料分拣主要依赖人工操作，存在以下问题：

1. **效率低下**：人工分拣速度受限，难以满足大规模订单处理需求
2. **错误率高**：长时间工作导致疲劳，容易出现错拣、漏拣
3. **人力成本高**：仓储分拣属于劳动密集型工作，人力成本持续上升
4. **管理困难**：人工操作难以实现实时数据采集和精细化管理

在此背景下，将机器视觉、深度学习和多传感器融合技术应用于仓储物料识别与分拣，具有重要的现实意义：

- **提升分拣效率**：自动化识别和分拣可大幅提升处理速度
- **降低错误率**：多维度校验机制有效减少误拣
- **实现数据驱动管理**：实时采集检测数据，支持库存精细化管理
- **推动智能制造发展**：符合工业4.0和智能制造的发展方向

### 1.2 国内外研究现状

**目标检测技术：**
目标检测是计算机视觉的核心任务之一。近年来，基于深度学习的目标检测算法取得了显著进展。2016年，Redmon等人提出YOLO（You Only Look Once）算法，将目标检测转化为回归问题，实现了端到端的实时检测。随后YOLO系列不断迭代，YOLOv8在精度和速度上达到了新的平衡，广泛应用于工业检测、自动驾驶等领域。

**多传感器融合技术：**
多传感器融合通过综合多个传感器的信息，获得比单一传感器更可靠、更全面的判断结果。在工业领域，常用的融合方法包括加权平均、卡尔曼滤波、D-S证据理论等。在仓储分拣场景中，融合视觉信息与重量传感器数据，可以有效校验识别结果的准确性，降低误拣率。

**异常检测技术：**
异常检测在工业质量控制、设备故障预测等领域有广泛应用。基于统计学习的异常检测方法（如Z-Score、控制图）通过建立正常行为基线，识别偏离正常范围的数据点。在仓储系统中，异常检测可用于发现低置信度识别、尺寸异常、重量异常等可疑情况。

**智能仓储系统：**
国内外企业和研究机构已开发了多种智能仓储系统。亚马逊的Kiva机器人系统、京东的无人仓、阿里的菜鸟网络等都实现了仓储自动化。但这些系统通常成本高昂，主要应用于大型物流中心。面向中小型仓储的低成本、可扩展的智能识别系统仍有较大发展空间。

## 2. 方案设计

### 2.1 系统总体架构

系统采用B/S（Browser/Server）架构，整体分为四层：

```
┌─────────────────────────────────────────────────────────┐
│                      表现层（前端）                         │
│  仪表盘 │ 物料检测 │ 库存管理 │ 传感器数据 │ 检测记录 │ 设置 │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP/RESTful API
┌──────────────────────────▼──────────────────────────────┐
│                      业务层（后端）                         │
│  检测服务 │ 库存服务 │ 传感器服务 │ 统计服务 │ 配置管理    │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│                      算法层                                │
│  目标检测(YOLO) │ 多传感器融合 │ 异常检测(统计学习)       │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│                      数据层                                │
│  SQLite数据库 │ 图像文件存储 │ 模型文件 │ 配置文件        │
└─────────────────────────────────────────────────────────┘
```

**各层职责：**
- **表现层**：负责用户交互和数据可视化，提供直观的操作界面
- **业务层**：负责业务逻辑处理，协调各模块工作，提供API接口
- **算法层**：负责核心算法实现，包括目标检测、多传感器融合、异常检测
- **数据层**：负责数据持久化存储，包括数据库、文件存储等

### 2.3 系统功能模块设计

#### 2.3.1 物料检测模块

该模块是系统的核心，实现从图像上传到完整检测结果输出的全流程：

1. **图像上传**：支持JPG/PNG/BMP格式，文件大小限制10MB
2. **目标检测**：调用YOLO模型进行推理，输出检测目标列表
3. **多传感器融合**：对每个检测目标，结合模拟传感器数据进行一致性校验
4. **异常检测**：对检测结果进行多维度异常分析
5. **结果存储**：将完整检测结果存入数据库
6. **库存更新**：对融合通过的目标，自动更新对应物料库存

#### 2.3.2 库存管理模块

实现仓储物料的库存管理功能：
- 库存列表查询（支持按类别筛选）
- 入库操作（增加库存数量）
- 出库操作（减少库存数量，含库存不足校验）
- 库存预警（自动标记低于最低库存和高于最高库存的物料）
- 库存项新增和删除

#### 2.3.3 传感器数据模块

管理传感器数据的采集和查询：
- 传感器数据上报API
- 历史数据查询（支持按类型、ID筛选）
- 统计分析（均值、最大值、最小值、标准差）

#### 2.3.4 检测记录模块

管理历史检测记录：
- 记录列表查询（支持按类别、融合结果筛选）
- 分页浏览
- 分拣状态更新（待分拣/分拣中/已分拣/失败）
- 记录删除

#### 2.3.5 统计仪表盘模块

提供系统运行概览：
- 核心指标卡片（总检测、今日检测、库存总量、异常数、通过率）
- 类别分布柱状图
- 近7天检测趋势图
- 最近检测记录列表
- 系统状态信息

#### 2.3.6 系统设置模块

提供系统参数配置：
- 检测参数（置信度阈值、IOU阈值）
- 融合参数（视觉权重、传感器权重、重量容差）
- 系统信息查看

## 3. 数据资源构建

### 3.1 数据集来源

本项目使用SORDI（Smart Object Recognition Dataset for Industry）工业数据集。该数据集由工业场景采集，包含丰富的仓储、生产环境物体类别，适合智能仓储系统的开发和测试。

**数据集基本信息：**
- 数据来源：公开工业数据集（SORDI）
- 数据规模：DR-1（9,325张）+ DR-2（36,943张）= 46,268张标注图像
- 标注格式：JSON格式（包含物体类别、边界框像素坐标）
- 图像分辨率：1280×720
- 物体类别：100+类工业场景物体

### 3.2 类别选择

从SORDI数据集中选择与仓储物料识别最相关的6个类别：

| 类别ID | 英文名称 | 中文名称 | 可用图片数 | 实例数 | 说明 |
|--------|----------|----------|-----------|--------|------|
| 0 | cardboard_box | 纸箱 | 17,165 | 33,741 | 快递盒、包装盒 |
| 1 | pallet | 托盘 | 34,850 | 179,864 | 仓储托盘 |
| 2 | stillage | 料架 | 42,690 | 361,979 | 笼车、物料架 |
| 3 | forklift | 叉车 | 23,913 | 24,805 | 搬运叉车 |
| 4 | eps_box | 泡沫箱 | 4,591 | 12,582 | 泡沫包装盒 |
| 5 | wheelie_bin | 滚轮料箱 | 7,952 | 7,952 | 滚轮料箱 |

选择依据：
1. **场景相关性**：均为仓储场景中常见的物料和设备
2. **类别多样性**：包含包装容器（纸箱、泡沫箱）、承载设备（托盘、料架）、搬运设备（叉车）、存储容器（滚轮料箱）
3. **数据充足性**：每类均有数千张以上图片，保证样本量
4. **可区分性**：各类别在形状、尺寸、外观上有明显差异，便于检测

### 3.3 数据采样

考虑到计算资源和项目规模，从每类中随机抽取400张图片，组成子集数据集：

- 每类采样数：400张
- 6类理论总数：2,400张
- 去重后实际总数：2,333张（部分图片包含多个类别，去重后减少）

采样方法：
1. 遍历所有标签文件，建立"类别→图片列表"映射
2. 对每个类别，随机打乱图片列表
3. 取前400张作为该类别的样本
4. 合并所有类别样本，按图片名去重

### 3.4 数据预处理

#### 3.4.1 标签格式转换

原始标签为JSON格式，需要转换为YOLO格式：

**原始JSON格式：**
```json
[
  {
    "Id": 32039,
    "ObjectClassName": "stillage",
    "ObjectClassId": 1004,
    "Left": 1095,
    "Top": 241,
    "Right": 1279,
    "Bottom": 504
  }
]
```

**YOLO格式（.txt）：**
```
2 0.927344 0.517361 0.143750 0.365278
```
格式说明：`class_id x_center y_center width height`，所有坐标归一化到0-1范围。

**转换步骤：**
1. 读取JSON标签文件
2. 过滤掉不在选定类别列表中的物体
3. 将类别ID映射为0-5的连续编号
4. 将像素坐标（Left, Top, Right, Bottom）转换为归一化中心坐标和宽高
5. 进行边界检查，确保坐标在0-1范围内
6. 写入YOLO格式的.txt文件

坐标转换公式：
```
x_center = (Left + Right) / 2 / image_width
y_center = (Top + Bottom) / 2 / image_height
width = (Right - Left) / image_width
height = (Bottom - Top) / image_height
```

#### 3.4.2 图像提取

从11.7GB的ZIP压缩包中直接提取选定的图像文件，避免全量解压：
1. 根据图片名在ZIP中定位文件
2. 直接读取并保存到目标目录
3. 重命名为`{数据集}_{原图名}.jpg`格式，避免命名冲突

#### 3.4.3 数据集划分

按7:2:1的比例随机划分为训练集、验证集、测试集：

| 数据集 | 数量 | 比例 | 用途 |
|--------|------|------|------|
| 训练集 | 1,633 | 70% | 模型训练 |
| 验证集 | 466 | 20% | 模型调优和验证 |
| 测试集 | 234 | 10% | 最终性能评估 |

划分方法：
1. 将所有样本随机打乱
2. 按比例切分为三个子集
3. 将图像和标签文件分别移动到对应目录

#### 3.4.4 配置文件生成

生成YOLO训练所需的配置文件`data.yaml`：
```yaml
path: /path/to/data/processed
train: images/train
val: images/val
test: images/test

names:
  0: cardboard_box
  1: pallet
  2: stillage
  3: forklift
  4: eps_box
  5: wheelie_bin
```

同时生成数据集索引CSV文件，记录每条数据的文件名、划分、包含类别等信息。

### 3.5 数据质量检查

预处理过程中执行以下质量检查：

1. **图像有效性检查**：验证图像文件可正常读取，剔除损坏文件
2. **标签匹配检查**：确保每张图像都有对应的标签文件
3. **标签格式校验**：检查YOLO格式的类别ID范围、坐标范围
4. **空标签过滤**：剔除不包含任何选定类别的图像
5. **类别平衡检查**：统计各类别样本数，确保分布合理

### 3.6 数据处理脚本

数据处理脚本位于`scripts/prepare_dataset.py`，主要功能：
- 从ZIP文件中扫描并建立类别索引
- 按类别抽样选择子集
- JSON标签转YOLO格式
- 图像提取和重命名
- 数据集划分
- 生成配置文件和索引

运行方式：
```bash
python scripts/prepare_dataset.py
```

### 4.3 算法模块实现

#### 4.3.1 目标检测算法（算法一）

**技术方向：** 机器视觉与深度学习

**文件位置：** `backend/algorithms/object_detection.py`

**核心类：** `ObjectDetector`

**功能实现：**

1. **模型加载**
   - 支持加载Ultralytics YOLOv8模型
   - 模型文件不存在时自动切换到模拟检测模式
   - 模拟模式基于图像特征生成合理的检测结果，用于系统演示和测试

2. **图像预处理**
   - 颜色空间转换（灰度→RGB，RGBA→RGB）
   - 等比例缩放至640×640
   - 居中填充（保持宽高比，不足部分补零）
   - 支持OpenCV和Pillow两种后端（自动适配）

3. **目标检测推理**
   - 模型模式：调用YOLO模型进行推理，设置置信度和IOU阈值
   - 模拟模式：基于图像亮度和纹理复杂度决定检测目标数量，生成随机但合理的检测结果
   - 返回检测结果列表（类别、置信度、边界框）和推理时间

4. **检测结果表示**
   - `DetectionResult`类封装单个检测结果
   - 包含类别ID、类别名称（中英文）、置信度、边界框坐标
   - 提供`to_dict()`方法用于序列化

**关键设计：**
- 采用单例模式，全局共享一个检测器实例
- 模拟检测模式确保系统在无模型、无GPU环境下仍可完整运行
- 图像预处理函数独立封装，便于测试和复用

#### 4.3.2 多传感器融合算法（算法二）

**技术方向：** 传感器与多源数据融合

**文件位置：** `backend/algorithms/sensor_fusion.py`

**核心类：** `MultiSensorFusion`

**功能实现：**

1. **传感器数据表示**
   - `SensorReading`类封装传感器读数
   - 包含传感器类型、ID、数值、单位、时间戳、可信度

2. **重量数据滤波**
   - 维护重量读数滑动窗口（最多10条）
   - 采用截尾均值滤波（去除最大值和最小值后取平均）
   - 有效抑制传感器噪声和异常读数

3. **重量一致性校验**
   - 预定义各类物料的理论重量范围
   - 应用容差比例（默认±30%）确定有效范围
   - 判断实测重量是否在预期范围内
   - 返回校验结果和原因描述

4. **加权融合决策**
   - 视觉权重0.6，传感器权重0.4
   - 综合置信度 = 视觉权重×视觉置信度 + 传感器权重×传感器可信度
   - 决策逻辑：
     - 红外未检测到物体 → 拒绝
     - 重量不匹配且视觉置信度低 → 拒绝
     - 重量不匹配但视觉置信度高 → 警告（送复检）
     - 综合置信度≥0.75 → 通过
     - 综合置信度0.5-0.75 → 警告
     - 综合置信度<0.5 → 拒绝

5. **传感器数据模拟**
   - 根据识别类别生成合理的重量数据（在理论范围内随机）
   - 生成红外到位信号（检测到物体）
   - 支持异常模式（生成超出范围的重量数据）

**融合结果表示：**
- `FusionResult`类封装融合判定结果
- 包含状态（pass/warning/reject）、综合置信度、最终类别、原因列表、视觉/传感器置信度、重量数据

**关键设计：**
- 采用轻量级的加权融合+规则校验方案，实现简单且可解释
- 视觉结果为主、传感器结果为辅，符合实际应用场景
- 详细的原因列表便于用户理解判定依据

#### 4.3.3 异常检测算法（算法三）

**技术方向：** 工业数据分析与异常检测

**文件位置：** `backend/algorithms/anomaly_detection.py`

**核心类：** `AnomalyDetector`

**功能实现：**

1. **历史数据维护**
   - 为每个类别维护独立的滑动窗口（默认100条）
   - 记录置信度、目标尺寸、重量等历史数据
   - 维护全局置信度历史和检测计数

2. **Z-Score计算**
   - 基于历史数据计算均值和标准差
   - Z-Score = |当前值 - 均值| / 标准差
   - 数据量不足（<5条）时返回0，避免误判

3. **多维度异常检测**

   **维度1：置信度异常**
   - 置信度<0.5 → 高异常分
   - Z-Score>3（临界值）→ 0.8分
   - Z-Score>2（警告值）→ 0.4分
   - 检测低置信度识别，可能意味着图像质量差、遮挡或新类别

   **维度2：目标尺寸异常**
   - 基于历史尺寸数据计算Z-Score
   - Z-Score>3 → 0.75分
   - Z-Score>2 → 0.35分
   - 检测远距离小目标、近距离大目标或误检

   **维度3：检测频率异常**
   - 检测间隔<0.1秒 → 0.6分（可能重复触发）
   - 检测间隔<0.3秒 → 0.25分
   - 检测传感器故障或重复检测

   **维度4：重量异常**
   - 基于历史重量数据计算Z-Score
   - Z-Score>3 → 0.8分
   - Z-Score>2 → 0.4分
   - 检测重量异常的物料

4. **综合异常评分**
   - 加权平均：置信度0.35 + 尺寸0.25 + 频率0.15 + 重量0.25
   - 异常等级判定：
     - 分数≥0.7 → 严重异常
     - 分数0.4-0.7 → 轻度异常
     - 分数<0.4 → 正常

**异常结果表示：**
- `AnomalyResult`类封装异常检测结果
- 包含是否异常、异常分数、异常等级、原因列表、各维度评分

**关键设计：**
- 基于统计学习的无监督异常检测，无需标注异常样本
- 多维度综合分析，减少单一维度的误判
- 滑动窗口机制适应数据分布的缓慢变化
- 详细的维度评分和原因列表便于问题定位

### 4.5 关键业务流程实现

#### 4.5.1 图像检测全流程

图像检测是系统最核心的业务流程，涉及三个算法模块的协同工作：

```
前端上传图像
    │
    ▼
后端接收文件（multipart/form-data）
    │
    ├─ 保存图像到uploads目录
    │
    ▼
目标检测模块
    │
    ├─ 读取图像文件
    ├─ 图像预处理（缩放、填充）
    ├─ YOLO推理 / 模拟检测
    └─ 返回检测目标列表
    │
    ▼  对每个检测目标：
    │
    ├──────────────────────────────────┐
    │                                   │
    ▼                                   ▼
多传感器融合模块                  异常检测模块
    │                                   │
    ├─ 生成模拟传感器数据               ├─ 置信度异常检测
    ├─ 红外到位检查                     ├─ 尺寸异常检测
    ├─ 重量滤波                         ├─ 频率异常检测
    ├─ 重量一致性校验                   ├─ 重量异常检测
    ├─ 加权融合决策                     └─ 综合评分+等级判定
    └─ 返回融合结果                     │
    │                                   │
    ▼                                   │
保存传感器数据到数据库 ◀───────────────┘
    │
    ▼
保存检测记录（含融合和异常结果）
    │
    ▼
融合通过 → 自动更新对应物料库存
    │
    ▼
返回完整结果（检测+融合+异常）给前端
    │
    ▼
前端展示结果，在图像上绘制检测框
```

#### 4.5.2 数据库事务处理

涉及数据修改的操作均使用数据库事务：
- 检测完成后，在一个事务中保存检测记录、传感器数据、更新库存
- 入库/出库操作使用事务保证库存数量一致性
- 操作失败时自动回滚，保证数据完整性

#### 5.4.2 遇到的问题及解决

**问题1：OpenCV库未安装导致图像预处理失败**
- 现象：`import cv2`报错，图像预处理功能不可用
- 解决：修改preprocess函数，增加try-except捕获ImportError，自动切换到Pillow后端进行图像缩放
- 结果：系统在有无OpenCV的环境下均可正常运行

**问题2：PowerShell中Python脚本的引号转义问题**
- 现象：在命令行中使用`python -c "..."`执行多行Python代码时，引号嵌套导致语法错误
- 解决：将测试代码写入独立的.py脚本文件，通过`python script.py`方式运行
- 结果：所有测试脚本正常执行

**问题3：大ZIP文件全量解压耗时过长**
- 现象：11.7GB的数据集ZIP文件全量解压需要大量时间和磁盘空间
- 解决：使用Python的zipfile库直接从ZIP中读取需要的文件，避免全量解压
- 结果：数据预处理脚本直接从ZIP中提取2333张图片和对应标签，耗时约2分钟

**问题4：模拟检测结果的随机性导致测试不稳定**
- 现象：模拟检测基于随机数生成结果，测试断言可能因随机性失败
- 解决：使用基于图像特征的固定随机种子（图像前10×10像素和），保证同一张图的检测结果一致
- 结果：测试结果稳定可复现

### 6.2 关键Prompt策略

在使用AI辅助开发时，采用以下Prompt策略：

1. **任务拆解**：将复杂任务分解为小的、明确的子任务，逐个请求AI完成
   - 示例："帮我写一个FastAPI的库存管理路由，包含增删改查和入库出库接口"

2. **约束说明**：明确技术栈、代码规范、输入输出格式等约束
   - 示例："使用SQLAlchemy 2.0语法，Pydantic v2模型，返回格式统一为JSON"

3. **上下文提供**：让AI先读取项目结构和相关代码，再进行修改
   - 示例："先看一下backend/models.py中的InventoryItem模型，然后帮我写对应的API路由"

4. **验收标准**：明确功能验收标准，便于验证AI生成的代码
   - 示例："要求支持按类别筛选、分页查询，出库时检查库存是否充足"

5. **逐步实现**：不要求AI一次性生成完整系统，而是分模块逐步实现和测试
   - 先写数据模型 → 再写API路由 → 再写前端页面 → 最后集成测试

6. **人工审查**：AI生成代码后，逐行阅读理解，检查逻辑正确性和安全性

### 6.3 AI出错案例及纠正过程

#### 案例1：数据库模型关系定义错误

**AI生成的代码问题：**
AI在生成SensorData模型时，将外键关联写在了错误的位置，导致`detection_record`反向关系无法正常工作。

**发现过程：**
运行数据库测试时，查询`SensorData.detection_record`返回None而非关联的DetectionRecord对象。

**纠正过程：**
1. 检查SQLAlchemy文档，确认relationship的正确用法
2. 将relationship定义移到DetectionRecord模型中，使用`backref`参数
3. 重新运行测试，验证关联查询正常

#### 案例2：前端Canvas绘图坐标计算错误

**AI生成的代码问题：**
AI在生成检测框绘制代码时，直接使用归一化坐标乘以画布宽度，没有考虑检测框坐标是中心点+宽高的格式，导致框的位置偏移。

**发现过程：**
上传检测图片后，绘制的检测框位置与实际目标位置不匹配。

**纠正过程：**
1. 仔细阅读YOLO坐标格式说明（x_center, y_center, width, height）
2. 修改绘图代码，先计算左上角坐标：`x = x_center - width/2`
3. 乘以缩放比例（画布尺寸/原图尺寸）
4. 重新测试，检测框位置正确

#### 案例3：多传感器融合逻辑中重量范围校验遗漏

**AI生成的代码问题：**
AI生成的重量校验函数只检查了重量是否超出上限，没有检查低于下限的情况，导致空箱等轻量物料被误判为正常。

**发现过程：**
手动测试时，输入一个非常小的重量值（0.1kg，纸箱理论范围0.5-25kg），系统返回"通过"，明显不合理。

**纠正过程：**
1. 检查重量校验逻辑，发现只判断了`weight > max`，缺少`weight < min`判断
2. 补充下限检查，分别给出"低于预期范围"和"高于预期范围"的原因描述
3. 增加对应的单元测试（test_weight_consistency_check_fail）
4. 重新测试，轻量和超重均能正确识别

### 7.3 创新点

1. **三算法协同的检测校验机制**：将目标检测、多传感器融合、异常检测三个算法串联工作，形成"识别→校验→预警"的完整质量保障链条，有效降低误拣率。

2. **无模型可运行的模拟模式**：目标检测模块在模型文件不存在时，自动切换到基于图像特征的模拟检测模式，保证系统在无GPU、无训练模型的环境下仍可完整演示和测试。

3. **基于统计学习的无监督异常检测**：采用Z-Score+滑动窗口的多维度异常检测方法，无需标注异常样本，通过历史数据自动建立正常基线，适应数据分布变化。

4. **轻量级多传感器融合方案**：采用加权平均+规则校验的轻量级融合方案，相比卡尔曼滤波、D-S证据理论等复杂方法，实现简单、可解释性强，适合课程设计和中小型应用场景。

5. **从大压缩包直接提取子集的数据处理方式**：针对11.7GB的大型数据集，采用直接从ZIP中读取所需文件的方式，避免全量解压，大幅减少磁盘空间需求和处理时间。

### 7.4 不足与局限

1. **模型训练未完成**：由于时间和计算资源限制，未实际训练YOLO模型，当前使用模拟检测模式。系统已预留模型加载接口，后续可加载训练好的模型。

2. **传感器数据为模拟生成**：当前版本的传感器数据（重量、红外）为程序模拟生成，未接入真实硬件。系统已设计传感器数据上报API，实际硬件接入只需编写对应驱动。

3. **机械臂分拣未实现**：系统设计了分拣状态管理，但未实际接入机械臂执行分拣动作。分拣功能目前停留在状态管理层面。

4. **前端技术较基础**：前端使用原生HTML/CSS/JS，未使用React/Vue等现代框架，在复杂交互和组件复用上有所不足。

5. **用户认证缺失**：当前系统未实现用户登录和权限管理，所有功能均可直接访问，不适合生产环境部署。

### 7.5 未来展望

1. **模型训练与优化**：使用处理好的数据集训练YOLOv8模型，实现真实的目标检测功能，并通过数据增强、迁移学习等手段提升检测精度。

2. **硬件接入与实物验证**：接入真实的工业相机、重量传感器、红外传感器和机械臂，在真实仓储场景中验证系统性能。

3. **实时视频流检测**：支持工业相机实时视频流接入，实现连续帧的目标检测和跟踪，而非当前的单张图像上传检测。

4. **用户系统与权限管理**：增加用户注册、登录、角色权限管理功能，支持多用户使用和操作审计。

5. **数据可视化增强**：引入ECharts等图表库，增强数据可视化能力，提供更丰富的统计分析和报表功能。

6. **部署与容器化**：使用Docker容器化部署，支持云端部署和横向扩展，提升系统可用性和可维护性。

7. **算法优化**：引入更先进的多传感器融合算法（如卡尔曼滤波、深度学习融合），提升融合精度和鲁棒性。
